## Change

Found a bounded-history defect in v0.8.5 `pruneRouteQueue`: only `delivered` records were treated as terminal history. Dashboard `resolve ambiguous` changes a route to `resolved`, so repeated manual resolutions could accumulate forever and defeat `MAX_ROUTE_RECORDS`.

v0.8.6 changes pruning semantics:

- active/nonterminal routes are always retained;
- both `delivered` and `resolved` are terminal history;
- terminal history shares the remaining `MAX_ROUTE_RECORDS` budget;
- terminal ordering uses `deliveredAt || resolvedAt` newest-first;
- active work is never discarded merely to satisfy the history cap.
